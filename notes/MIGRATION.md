Goal: every layer of the release under **`/ccn2b/dataset/babyview/2026.1/`**, one key
convention, pose-README-grade documentation per layer, one standing verification script
instead of per-analysis special-casing. Actual moves, not symlinks.

## 0. The key convention (verified on disk, not assumed)

Canonical id = the **release name**: `S00220001_2024-02-05_1_recfcw2yqs02gdskT`
(+ `_rotated` where the video was reprocessed rotated; the rotated dir *replaces* the plain
one — verified zero coexistence across 16,299 pose dirs). Crosswalks:

- → Airtable row: trailing `rec[A-Za-z0-9]{14,}` == `unique_video_id` (bare rec-id; immutable)
- → child: `subject_id`; within-video: `frame_idx` (= second, 1 fps) / `utterance_id`

Verified agreement TODAY: frames dirs == release list **exactly** (0/0 diff); transcript
video_ids ⊂ release list **exactly** (16,008 of 16,306 have speech); pose dirs match except
**10 missing** (sub-second S00270001 clips, documented) and **3 extra** (post-release
2026-05 recordings — quarantine). Pairs/Gemini/language/embeddings inherit the transcript
key, so they conform by construction.

Deviations to fix — only two:
1. `pose_1fps_bbox_limbs.csv` keys on column `superseded_gcp_name_feb25` + `H:MM:SS` time.
2. Consumers must regex-extract the rec-id to reach Airtable.

## 2. Quality controls (the pose-README standard, made mechanical)

- Per-layer README: method, model + env pins, date, **join key**, coverage vs 16,306,
  known gaps, reader snippet.
- `outputs/MANIFEST.tsv`: per-file md5 + row count + generation date, regenerated by the
  migration script, checked by the verifier.
- **`src/verify_release.py`** — the standing check, run after migration and before any
  experiment bundle: every layer joins to `release_index.tsv` at its declared key; coverage
  ≥ documented floor; key dtypes; no orphan ids; row counts == MANIFEST. Output committed to
  `diagnostics/`. This is what replaces the ad-hoc special-case hunting.
- `make_diagnostics.py` + `supplement.qmd` re-run against the NEW paths; the coverage figure
  becomes the eyeball check.

## 3. Sequencing

1. **Wait for jobs** (embeddings resume; Gemini pass 1; diagnostics). Nothing moves while a
   job holds a source or target path open — editing-under-a-running-job already burned us.
2. Migration script with `--dry-run` default: prints every copy/rename with sizes; writes
   `migration_log.tsv` (old path, new path, md5) for reversibility.
3. Execute copies (M1–M4): **copy → md5 verify → only then retire source** (`MOVED.txt`
   breadcrumb at every old location pointing at the new path + the log).
4. Pose rekey (M5–M6), embedding merge (M7), index + READMEs (M8–M9).
5. `verify_release.py` full pass; rerun diagnostics; fix anything red.
6. Repo repoint: `common.py` release roots, run scripts, `bv-annotations` pose readers —
   one grep sweep per repo, committed together with the log.
7. Oak mirror (below); only after Oak verify do the old `/ccn2a`+`/ccn2` copies get deleted.

## 4. Risks and mitigations

| Risk | Mitigation |
|---|---|
| in-flight jobs read a moving path | hard sequencing: migrate only after bundle-1 jobs finish; verify with `pgrep` before each phase |
| copy corruption / partial copy | rsync `-c`, md5 in `migration_log.tsv`, verify before retiring source; never cross-fs `mv` |
| feb25 names drifted from current registry | rec-id-mediated remap with 1:1 assertion — drift becomes a loud error |
| breaking other people's consumers (khaiaw, bv-annotations, book scripts) | `MOVED.txt` breadcrumbs; grep sweep of our repos; team announcement before the retire step; old copies survive until Oak-verified |
| deleting the wrong thing | archive-then-verify-then-free (standing rule); nothing deleted until Oak mirror verified; dry-run default |
| partially-complete layer copied as complete | migration script checks row counts vs expected (e.g. language = 1,838,288 utterances) before copying |
| `/ccn2b` df anomaly (reports 1.0M used against ~650G on disk) | confirm quota/export config with admin before adding ~50G; `df` avail says 1.6T but the inconsistency should be understood first |
| silent key mismatch (the recurring failure class) | `release_index.tsv` + verify_release.py make every join checked; no consumer regexes ids |

## 5. Oak mirror — recommendation: yes, scoped

Mirror the **irreplaceable/derived** layers right after verification (≈ **72G** total —
trivial against the 10TB allocation): annotations (referent ~28M — ~$255 of Gemini credits,
currently the single most at-risk asset; language 1.6G — ~$400 across releases), transcripts
397M, pose parquet + pkls ~25G, embeddings ~43G (regenerable but ~a GPU-day), registry
snapshot + id lists + MANIFEST.

**Frames (609G): do not duplicate.** Raw videos are canonical on GCS and Alvin is already
migrating them to Oak; frames are deterministically regenerable (recipe + env pinned in
`README_pose_1fps.md`). Coordinate with Alvin so the video archive and this mirror don't
overlap. Transfer via `oak-dtn` (key-based, Duo-free); verify with size+md5 listing on the
Oak side; record the mirror date in MANIFEST.
